# Return Merchandise Authorization Tracker
A Google Sheets RMA case tracker that can generate / import RMA data and analyze that data's trends.

## Overview
The tracker was made as a practice project so simulate a real production enviroment for someone that works in a logistics data analyst role. The data generation feature creates data sets that mimic real life enviroments by including multiple vendors, part numbers based on vendors, case creation dates based on the current date, records that change based on RMA status, and SLAs based on vendor details.

## Instructions
A view only version of the tracker can be seen [here](https://docs.google.com/spreadsheets/d/14JjhwpA3bJYxzZtpKqgT-om5JD4g2ygPh9on_iwDqBU/edit?pli=1&gid=0#gid=0).

To use the GENERATE DATA and IMPORT DATA buttons you can access the project using the link and make a copy of the project under File -> Make a copy. In the copy, you can use the GENERATE DATA or IMPORT DATA buttons to populate the sheet. The first time you click these buttons a prompt will appear requesting authorization access to run the macros. Upon accepting the request the functionality of the buttons should run as expected. 

In the Data tab there is also a filter view to see the cases by creation date. This can be found under Data -> Change View -> Sort by Creation Date. If new data is generated while the filter view is in place you will have to exit and reenter the filter view for the records to be sorted again.

## Project Structure
The project is separated into multiple tabs that perform different functions by feeding data through each tab. The structure goes as follows:

RMA Data -> Pivot Summary -> Dashboard

### Data Tab
The data tab holds all information about the RMA records. Each record has it's own RMA ID, part number, SN, case creation date, RMA status, case closure date, case age, as well as information about the SLA, the SLA status of the record, and the SLA days remaining. Each column is color coordinated to represent how the data is set:

Green = Macro generated, not editable. The data is generated by the GENERATE DATA, or IMPORT DATA buttons. This data is set on record creation and is not to be changed by the user.

Yellow = Macro generated editable. These fields are also generated by the macro but can be changed by the user.

Blue = Formula generated. These fields are generated after other record data is generated using built in formulas.

All the macro generated fields are randomly generated upon pressing either of the data modifying buttons. To simulate a real life enviroment, the records are randomly generated but some fields have special conditions. RMA IDs and SNs are always unique even across multiple vendors. The part number is choosen by looking at part number pools determined by the vendor. Each vendor may distribute different kinds of parts and by having separate pools, each record will have one of these part numbers based on what the vendor stocks. The creation date is based on a range determined by a set date (data generation / load date) to reflect a working enviroment. 

The RMA status is randomly generated but can be changed by the user if progress on a case changes. If a case is closed the closure date and SLA status and SLA days remaining dynamically change as well.

The SLA columns use multiple formulas to populate it's data. The SLA (Service Level Agreement) is the agreement between a logistics provider and the vendor that determines when an in warranty part should be returned after it is determined that the part is defective. Each vendor has their own SLA and each record has its own status based on the specific SLA for the vendor. The SLA status can either be `WITHIN SLA`, `BREACHED SLA`, or `COMPLETE` based on the RMA status and age. If the RMA age is within the vendors SLA then the SLA is not breached but as soon as the RMA age exceeds the vendor SLA then the SLA status will be breached. Closed RMA cases will change the SLA status to complete which can be done by the user when closing a case.

## Pivot Summary Tab
The Pivot Summary tab holds pivot tables and other information that is pulled from the data tab and then fed to the dashboard. There are several pivot tables which can gather different data elements from the data tab. There are some simple pivots that organize data like number of RMAs by vendor and number of RMAs by RMA status or SLA status. There are other pivots and tables that take the average age of RMAs by vendor or take the RMAs by status per 30 day periods. These two in particular track the performance of the vendor or the logistics providers performance over time. Having this data readily available makes it easier to build visual charts rather than just looking at numbers.

## Dashboard Tab
The dashboard tab creates a visual overview of the data and makes it easier to parse the information to come to conclusions about the current RMA cases. There are example KPI cards that give quick information on the current workload of the project. These indicators include total RMA cases, open and in progress RMAs, as well as the average age of all the RMAs. Additionally there are charts that show important performance metrics such as breached SLAs by vendor or RMA cases by status in 30 day periods. Both of the mentioned charts focus on RMA performance, one by the vendor and the other by the status of the RMAs. A vendor that has many breached SLAs could point to issues servicing the specific vendor and many breached RMAS in a certain 30 day period may indicate problems closing out records from that period.

## Technical Implementation
The entire project is included in the Google sheets link above and the code for the macros can be found in the scripts folder. The main macros for the project are the `generateData()` and `importData()` functions which are tied to the buttons on the data tab. The `generateData()` function randomly creates 100 records for the rest of the project to use. Most dates in the project are tied to the `LAST_UPDATED_DATE_CELL` which is populated with the last time the `generateData()` or `importData()` functions have been called. In a real enviroment the `TODAY()` formula should be used instead to track cases in real time but as this is a test project the case for basing dates on a "snapshot" fits much better. If `TODAY()` was used in the current project then data like the SLA status could change if the data is not regenerated / reloaded as dates roll over. The `importData()` function pulls an example set of data from this repo under the `data/rma_data.csv`. This example set was actually generated using the `generateData()` function but anyone could modify the import function to pull from a different data set if needed.

Multiple formulas are also showcased in this project between different tabs. `XLOOKUP` is used to pull the Vendor SLAs on the Data tab by taking the vendor of each record and comparing it to a table in the Vendor Settings tab. `IFS` is used to determine the SLA Status of each record by comparing the SLA days and the RMA age but also by checking the case to see if it is closed. In the Pivot Summary tab `COUNTIFS` is used to get the number of cases in each 30 day period and categorizes them by the RMA status. `ARRAYFORMULA` is also used to apply other formulas to the entire column. This can be seen with all the SLA columns in the Data tab.
